# 极限竞速 · LAN —— 实机联机指南

> 交付物：**`ForzaLAN.exe`**（单文件，6.5 MB，双击即用）
> 全部前端资源（three.js / cannon-es / HTML / CSS / 业务脚本）已编译期内嵌。
> **运行期零外部网络请求** —— 断网路由器下开箱即用。

---

## 1. 主机启动

### 双击运行（最简单）
直接双击 `ForzaLAN.exe`。控制台会打印：

```
  ┌───────────────────────────────────────────────────────────┐
  │   极限竞速 · LAN   12人局域网 3D 网页赛车（全离线单文件）  │
  └───────────────────────────────────────────────────────────┘

   本机访问      http://localhost:8099
   局域网访问    http://192.168.100.148:8099      ← 把这个地址给同学

   同一 Wi-Fi / 交换机下，让其他 3 位玩家在浏览器打开上面的局域网地址即可。
```

**把「局域网访问」那一行的地址抄给同学。** 若打印出多条（多网卡/虚拟机），
选与同学同一网段的那条（通常是 `192.168.x.x` 开头）。

### 命令行启动（需要改端口/圈数时）

| 参数 | 说明 | 示例 |
|---|---|---|
| `-addr` | 监听地址，默认 `:8099` | `ForzaLAN.exe -addr :9000` |
| `-laps` | 默认圈数，默认 3 | `ForzaLAN.exe -laps 5` |
| `-quiet` | 关闭逐帧日志（比赛时更清爽） | `ForzaLAN.exe -quiet` |

环境变量 `PORT` 也可指定端口（优先级：`-addr` > `PORT` > 8099）。

### 确认 IP 与端口

```bash
# 看端口是否在监听
netstat -ano | findstr ":8099.*LISTENING"

# 看本机所有 IPv4 地址（挑 192.168.x.x / 10.x.x.x 那个）
ipconfig | findstr "IPv4"
```

### 放行防火墙（首次运行必做）
Windows 会弹「是否允许 ForzaLAN 通过防火墙」→ **勾选「专用网络」并允许**。
若当时点了拒绝，同学会连不上（表现为一直卡在「正在探测服务端…」）。补救：
控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 → 找到 `ForzaLAN.exe` 勾选专用。

## 2. 同学连接流程（其余 3 人）

**前提**：与主机在同一 Wi-Fi / 同一交换机下。

### 第 1 步：打开页面
浏览器地址栏输入主机给你的地址，例如 `http://192.168.100.148:8099`
➡ 看到「极限竞速 · LAN」大厅界面，底部「正在探测服务端…」变为已连接。

> 支持 Chrome / Edge 97+、Firefox 102+、Safari 16.4+。
> **不要用 `file://` 打开 HTML**，必须通过 `http://` 地址访问。

### 第 2 步：填写个人信息（房主与同学都一样）
- **车手昵称**：最多 12 字，如「阿强」
- **车身颜色**：点色块选择
- **比赛圈数**：1 / 3 / 5 / 8 圈（**只有房主的选择生效**）
- **赛道**：铃鹿 8 字 / 拉斯维加斯夜赛 / 斯帕 / 新手·极简高速环道（**只有房主生效**）
  - 「新手·极简高速环道」是合成入门图：两条 400m 大直道 + 两个半径 180m 的宽弯，
    周长约 1931m，无急弯、无立交、无窄口，护栏外还有约 5.8m 缓冲 —— 适合第一次上手与练跟车。
- **碰撞模式**：可勾选「全员幽灵车模式」（车与车不碰撞、可互相穿透、保留吸尾流）

### 第 3 步：房主创建 / 同学加入

**房主**：点「创建房间」→ 界面切到房间页，顶部显示 **4 位房间号**（如 `A7K2`）。
➡ **把这 4 位字符念给同学。**

**同学**：在「房间号」输入框填入 4 位字符 → 点「加入」（或直接按 Enter）。

### 第 4 步：赛道与模式确认
房主在房间内可点「切换赛道」「切换模式」，**其余玩家的界面会同步更新**。
房间内能看到各席位与各自准备状态（**上限 12 席**）。

### 第 5 步：准备 → 自动发车
每人点一次「准备」（按钮变「取消准备」）。
➡ **全员准备后先进行 5 秒整备倒计时，再经过 250ms 载入缓冲和 5×700ms 红灯序列，自动进入比赛。** 无需房主额外点开始。

> 想自己先练手：大厅里的「**单机练习（11 台 AI 车手 · 不联网）**」，
> 不占端口、不需要其他玩家。

## 3. 完整操作快捷键

| 按键 | 功能 |
|---|---|
| **W** / **↑** | 油门 |
| **S** / **↓** | 刹车（停住后继续按 = 倒车） |
| **A / D** 或 **← / →** | 转向 |
| **空格** | 手刹（漂移用） |
| **C** 或 **V** | 切换视角：第三人称追尾 → 引擎盖 → 垂直鸟瞰（循环） |
| **← / →** | **完赛后**切换观战对象（接力看完整场比赛） |
| **R** | 脱困复位：瞬移回**驶出赛道前最后一个合法位姿**，继承约 6 成出界前车速，罚时 +3.0s，随后 3.5s 幽灵化可立即起步 |
| **L** | 最佳走线显示开关 |
| **M** | 音效开关 |

**完赛之后**：本地操控权剥离，赛车切入 **60 km/h 自动巡航**沿最佳走线慢游（不挡终点线），
镜头切成观战视角，可按 `←` / `→` 在剩余车手之间切换。
**首位车手冲线后启动 60 秒 DNF 宽限倒计时**：到点仍未冲线的车手按当前进度判 DNF（未完赛），全场结算。

## 4. 实机联机冒烟测试清单（5 项核心检验）

发车后按顺序过一遍，**每项都有明确的肉眼判据**。

### ① 多车无闪现抽搐（网络同步）
**怎么验**：所有人上赛道跑起来，观察**别人车**的运动。
**通过判据**：
- 车身连贯前进，**没有周期性的「一顿一顿」或瞬移拉丝**
- 高速超车时对方车辆平滑掠过，不出现「突然后退半米再弹回」
- 多车同时挤在一个弯道，画面不卡顿崩坏

> 底层保障：Dual-Layer 误差融合 + 20Hz 指数衰减（`exp(-20dt)`），
> 无头仿真实测单帧位移超限 **0 次**、Jerk 尖峰 **0 次**。

### ② R 键精准回驶出点
**怎么验**：故意开出赛道冲进沙地/草地 → 停住 → 按 **R**。
**通过判据**：
- 车回到**脱离赛道前那一下的沥青位置**（不是回到起跑线、也不是回上一个检查点）
- 朝向与冲出时一致（车头方向对）
- 计时塔「处罚」列 **+3.0s**，违规次数 +1
- 复位后车半透明约 3.5 秒，**期间可以直接踩油门起步**（不会被冻住）
- 本圈成绩作废（冲线时不计入最佳单圈）

### ③ 护栏不可穿透
**怎么验**：找一段直道，**全油门 200km/h 以上正面撞护栏**；再试斜角度擦撞。
**通过判据**：
- 车被**挡在护栏内侧**，绝不穿到外面去
- 撞完**不弹飞、不飞起**（法向反弹接近 0，车贴在护栏上减速滑行）
- 连续贴护栏刮擦，不出现「车穿墙而出」或「车被弹到赛道另一侧」

> 底层保障：护栏碰撞体厚 **2.0m**（半厚 1.0）＋ 单子步位移上限 **0.03m**，
> 实测 200km/h 撞墙反弹 **1.146 → 0.0071 m/s**。

### ④ 左上角 F1 计时塔秒差实时刷新
**怎么验**：多车在赛道上拉开距离，盯左上角计时塔的时间差距列。
**通过判据**：
- 每行显示与**本地玩家**的实时差距，数字**每秒都在跳动**
- **自己那一行**显示 `--`（或为 P1 时显示领跑标记），有微弱蓝色高亮
- 落后本地玩家显示 `-0.X`，领先本地玩家显示 `+X.X`
- 右侧橙黄色「处罚」列累计罚时与违规次数同步更新
- 名次随实际超车**实时换位**

### ⑤ 吃尾流：气流微颤 + 极速收益
**怎么验**：紧跟前车（约 1~2 个车身）进入尾流锥形区保持几秒。
**通过判据**：
- 车尾两侧出现**细微的透明流动气流线**（涡线，淡白色细带）
- 座舱视角有**高频轻微颠簸**（24Hz 气流震颤）
- 视线（FOV）**微收 1.5°**
- 尾速**明显高于**单独跑时的极速（正面风阻降低 35%）
- 一旦偏出锥形区，上述视效立即消失

## 5. 控制台报错一键排查

**如果按 F12 看到红色报错**，先跑这条命令自查（在项目目录下）：

```bash
node tools/e2e.mjs 2>&1 | tail -20
```

`e2e.mjs` 会做三件事：① 静态扫描全部前端文件有无外链字面量（零外链红线）；
② 真起 `forzalan.exe` 走一遍真实 WebSocket 全流程；③ 校验内嵌资源完整性。
**128 项全过 = 前端与二进制本身没问题**，报错多半在浏览器侧。

### 常见报错对照

| 控制台现象 | 原因 | 一键排查 / 解决 |
|---|---|---|
| 卡在「正在装载本地离线引擎…」 | 用 `file://` 打开了 HTML | 改用 `http://主机IP:8099` 访问 |
| 一直「正在探测服务端…」 | 连不上主机 | 见下方网络排查 |
| `CSP violation` / 资源被拒 | 有外链被 CSP 拦截 | 跑 `node tools/e2e.mjs`，静态扫描会指名道姓 |
| `/js/main.js` 404 且标题是 `CEF remote debugging` | **8080 端口被 Steam 占用** | 换 8099：`ForzaLAN.exe -addr :8099` |
| WebAssembly 相关警告 | 老浏览器不支持 `wasm-unsafe-eval` | **可忽略**，纯 JS 物理路径自动接管 |
| **画面很卡 / 车一顶一顶 / 左上角秒差乱跳几百秒** | **跑的是旧 exe**（内嵌资源陈旧），或改过 `public/js` 没重编 | 重编并把 3 个门禁跑绿：`go build -trimpath -ldflags "-s -w" -o forzalan.exe .` → `node tools/perf-probe.mjs`（帧间隔 p50 应 ≈8ms）→ `node tools/hud-gap-probe.mjs` |

### 网络连不上一键排查

```bash
# 1. 主机上确认端口在监听
netstat -ano | findstr ":8099.*LISTENING"

# 2. 若有残留进程占着端口，先杀掉（否则新服务绑定失败但不报错）
for /f "tokens=5" %a in ('netstat -ano ^| findstr ":8099.*LISTENING"') do taskkill /F /PID %a

# 3. 同学侧确认能 ping 通主机
ping 192.168.100.148
```

- 不通 → 检查是否**同一 Wi-Fi**（别一个连 5G 热点一个连有线不同网段）
- 通但打不开 → 主机的**防火墙**没放行 `ForzaLAN.exe`（见第 1 节）
- 换端口再试：`ForzaLAN.exe -addr :9000`，同学访问 `http://主机IP:9000`

### 6.3 铃鹿赛道：真实走线重建（2026-09-30）

**用户诉求**：「这铃鹿赛道跟 fm8 的一点也不一样啊，对铃鹿赛道完全重构，要求与 fm8 中的
铃鹿赛道完全一致 —— 赛道宽度、护栏位置；赛道外的装饰可以适当简化，有地标性建筑即可。」

**原实现的根本问题**：`suzukaDef` 是**程序化生成**的 `x=A·sin(u), z=B·sin(2u)` 双纽线，
再叠加随 seed 变化的径向调制 —— 形状、弯序、宽度都与真车无关，每换一个 seed 就是另一条
"铃鹿"。所以之前无论怎么调参都不可能"像铃鹿"。

**新实现：OSM 实测走线 + 真车参数量化**

| 项目 | 来源 / 数值 |
|---|---|
| 走线 | OpenStreetMap `relation 284570`（`type=circuit`、`name=鈴鹿サーキット`） |
| 数据文件 | `public/js/suzuka-geometry.js`（**离线烘焙**，游戏运行期不联网） |
| 导入脚本 | `tools/import-suzuka-osm.mjs`（OSM XML → 拼环 → 清洗 → 投影）+ `tools/suzuka-orient.mjs`（定行车方向与起终点，`--write` 烘焙） |
| 周长 | **5795m**（OSM 中心线）／**5797m**（重建后等弧长） vs 真车 **5807m** ⇒ 偏差 **−0.17%** |
| 8 字形自交 | 投影上**恰好 1 处**（真车立体交叉的唯一交点） |
| 最小弯半径 | **13.8m**（真车发卡 ≈14m） |
| 起终点 | 由真车公布坐标（34°50'35.48"N 136°32'26.58"E）落点，距折线最近点 **19m**；与"主直道距 1 号弯"启发式互校差 **77m** |
| 行车方向 | 18 个含弯名的 OSM way 里 **16 条指向一致**（另 1 条相反、1 条为发卡顶点交叉）；弯序在索引递增方向上单调，与真车弯序一致 |
| 弯名核对 | メインストレート / 1コーナー / 2コーナー / S字 / デグナー1・2 / NISSINブレーキヘアピン / スプーンカーブ / 130R / 日立Astemoシケイン / 西ストレート 全部映射到位（误差 ≤34m） |
| 赛道宽度 | 真车公布 10~16m；按"路段性质"重建为**逐点半宽**（主直道 16m、高速弯 14m、S 字/德格纳 12m、发卡与减速弯 11m），沥青/白线/路肩/缓冲区/护栏全部跟随 |
| 护栏位置 | 逐点变位 = **半宽(逐点) + 路肩 + 缓冲区 9m**（真车永久赛道护栏在缓冲区外沿的惯例） |
| 立交 | 交点由**构造期在最终等弧长几何上**定位，并按"必须净空被跨那一层"自动加高（见下） |

**如实说明数据精度**：OSM 只提供**中心线**，不含路宽与护栏线。所以「走线」是实测数据，
而「宽度 / 护栏位置」是在真车公布区间（10~16m、永久赛道护栏惯例）内的**重建**，
不是逐米实测值。要做到逐米一致需要真车的赛道模型数据，本项目没有（也不应从商业游戏里
提取资源）。**高程**同理：OSM 无高程，剖面是按真车性格重建的（低频起伏 + 立交抬升）。

**重建过程中查出并修掉的 5 个真问题**（都由实测暴露，不是猜的）：

1. **零长度重复点 ⇒ 179° 尖点**：OSM 节点里有一对完全重合的点，Catmull-Rom 在该处切线
   退化为零向量，重采样后出现 **179° 折返、半径 1.5m**。修法：导入时去重复点 + 细分长段
   （OSM 在直道上缺顶点，最长 346m）。修后最小半径 13.8m、最大单点转折 30°。
2. **`baseY` / 立交中心写死 v≈0**：真实立交在 v=79.55%，而 Track 构造 `baseY`（桥下地面层、
   地物落位、分层判别的共同依据）时用的是写死的 v≈0 ⇒ 全错。改为由 `def.bridgePct` +
   `def.liftAt` 驱动（两者同源，不会漂移）。
3. **地形起伏把桥面抬升抵消掉**：起伏幅度 ±7.6m 与 `BRIDGE_Y=7.5m` 同量级，实测立交处
   上下两层只剩 **0.84m** 高差（比净空 1.0m 还小 ⇒ 车会从桥面掉下去）。修法：桥面高度
   写成 `max(base(本层), base(被跨层) + 净空 + 余量)`，即**保证净空**而不是固定 +7.5m。
4. **额外抬高只加在桥区 ⇒ 45% 台阶坡**：额外量按 `onIdx` 逐点施加，而区边界上 bump=0.5
   ⇒ 边界处直接跳 ~1.7m，实测**相邻 4.5m 内抬高 2.04m（45% 坡）**，车辆贴地约束失效。
   修法：按 bump 包络**全程加权**施加（引桥外 bump≡0，天然平滑），修后最大坡 11%。
5. **宽相网格边界**：±1000m 之类的硬编码常量装不下真实铃鹿（护栏包围盒
   x[-1189,1075] z[-752,590]），越界刚体会被挤进边缘 bin。修法：按
   **静态刚体实际位置**（取两个半轴中较大者作保守上界）推导，不写坐标字面量。
