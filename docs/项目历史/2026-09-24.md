### 本轮真正改的（3 处）
1. **`BARRIER_RESTITUTION` 0.0 → 0.02** —— 规格明确"车辆与车辆、车辆与护栏的
   contactMaterial.restitution 设为 0.02"，护栏原来单独设了 0。
2. **预测性幽灵化的透明度改为指数缓动**：原来直接把 `c.pgGhost`（0/1）喂给
   `applyGhost`，解除隔离瞬间 0.35 → 1.0 是硬跳。规格要求"平滑淡入透明度"，
   改为渲染层维护 `ud._pgAmt` 用 `1 - exp(-12*dt)` 缓动逼近目标（收敛后精确贴合，
   避免每帧重写材质）。
3. 修两处**陈旧注释**：尾流镜头湍流写成 "25Hz / 0.015m"，实际常量是 24Hz / 0.012m（规格值）。

### 用户的两个架构决策（本轮问过）
- **时钟微调**：选**时间基微调、保固定步长**。即 ±1.5% 加在"本地时间轴 → 服务端时间轴"
  的映射上（`S.simOffset`），物理永远严格 1/60。**不要**改成 `adjustedDt` 变速推进物理 ——
  那会毁掉累积器/子步插值/确定性仿真与三层测试的前提。
- **双层误差融合**：选**叠加在现有插值之上**。保留 30 帧环形缓冲 + 自适应 renderDelay +
  Hermite/SLERP（负责时间轴对齐），双层 phys/visualOffset 负责残余突变。

## 第八轮：按 ForzaTech 的 ResolveNetworkContact 优化撞车解算（抓到硬编码恢复系数）

用户贴了 FM8 网络物理管线的**算法说明 + C++ 参考实现**，要求"仿照 FM8 碰撞代码优化碰撞"。
逐条对照后：时钟 slew / 航位推测 / 双层误差融合 / 预测幽灵 **都已在库**（第 5、7 轮已确认），
真正的问题在 **`onCarCollide` 自己写的那段冲量解算**里。

### 抓到的真 bug（就是"撞车弹跳 / 炸车"的直接原因）
`physics.js` 的 `onCarCollide`：
```js
const eRest = 0.3;                                     // ← 硬编码，不是 CFG.RESTITUTION(0.05)！
const J = (1 + eRest) * closing / (1/ma + 1/mb);        // ← 纯弹性，无 Baumgarte、无冲量上限
```
`CFG.RESTITUTION / BAUMGARTE_BIAS_V / BAUMGARTE_IMPULSE` 这几个常量**只被
`absorbSoftContacts` / `resolveRam` 用**，主撞车路径完全没走 —— 等于规格参数根本没接上。

还有第二处反向 bug：
```js
const rvn = rv·n;
if (rvn > 0) { n = -n; }        // 翻转法线后一律按"接近"处理
const closing = Math.abs(rvn);
```
翻转法线**不改变是否接近**，所以这等价于给**正在分离**的两车施加吸引力 ->
车贴一起"粘住"、反复小弹跳。

### 按参考实现改的
1. **分离早退**：`if (rvn > 0) return;`（对应参考代码的 `normalVel > 0 -> return 0`），
   法线不再翻转（cannon 的 `ni` 本就指向"推开 A"）。
2. **软约束冲量三件套**：
   `pen = |contact.penetrationVec · n|`（cannon **暴露** `penetrationVec`，实测可用）；
   `biasVel = min((CFG.BAUMGARTE_BETA/dt)·pen, BAUMGARTE_BIAS_V=2.5)`；
   `deltaV = (1 + CFG.RESTITUTION)·closing + biasVel`；
   `J = min(deltaV/invSum, BAUMGARTE_IMPULSE=50000)`。
   新增 `CFG.BAUMGARTE_BETA = 0.2`。
3. 行为断言：两车 40m/s 对撞，**反弹系数 0.000**（旧代码按 eRest=0.3 会是 ~12m/s），
   且 maxV / maxVy 都在安全范围（没被轰上天）。

### 台架踩坑
判据别把"接近速度"当"反弹速度"：`rel = (vA−vB)·f > 0 是接近、< 0 才是分离`。
第一版写成 `if (rel > 0.2) rebound = rel` -> 撞前就一直是 40，测出 1.000 的假失败。

### 验证
selftest **334/334** · track-verify **77/77** · e2e **72/72** · `go vet` / `go test` 干净 · build OK。

## 第十轮：修复"三赛道护栏全都能穿过去" + 铃鹿看台长在赛道上

### 根因（严重，且暴露了我自己的验证漏洞）
`track.js` 的 `registerTrackBodies()` 里有一行守卫：
```js
if (typeof CANNON === 'undefined') return [];
```
**但 track.js 从来没有 import CANNON**，而 `libs/cannon-es.js` 是 **ESM**（不会像 UMD 的
three.min.js 那样产生全局变量）。于是这个守卫**在浏览器里也恒为真**，函数永远返回 `[]`。

调用方 physics.js 明明调了、也把返回值存进了 `this.staticBodies` —— 但存的是空数组。
**三大赛道的护栏 / 桥栏 / 桥墩全程只是视觉装饰，车直接穿出去。**
实测三个赛道的 `world.bodies` 里静态体数量都是 **0**。

第 4 轮我以为"加了 `registerTrackBodies` 调用"就修好了，**但从没断言过它的效果**
（只断言了车车碰撞、幽灵模式这些走别条路的性质）。教训：
**"断言调用发生了" ≠ "断言效果发生了"。** 凡是"把数据落进另一个系统"的函数，
测试必须数**目标系统里的对象数**，不能只数调用次数或返回值非空。

### 修法
`track.js` 加 `import * as CANNON from '../libs/cannon-es.js';`，删掉那个会骗人的守卫。
修后静态体：suzuka **803**、vegas **720**、spa **720**。

### 写文档时自查出的一条关键事实（重要，以后别搞错）
`physics.js:1394` 的 `onCarCollide` 开头是：
```js
if (!other || !other.__carId) return;      // 静态护栏没有 __carId
```
**静态护栏撞墙根本不走本工程的自定义解算**，全程是 cannon 默认解算器。
所以"撞墙被弹飞"和"撞车被弹开"是**两个不同的根因**：
- **撞墙**：cannon `ContactEquation` 内部把穿透折成偏置项 `b` 加进**速度约束**求解
  （`contactEquationStiffness = 5e5` / `relaxation = 6`）-> 同样是"位置误差注入动能"。
- **撞车**：本工程 `onCarCollide` 里显式写的 `deltaV = (1+e)·closing + biasVel`。
  同一个病，但**修法不同**：撞车删那一行就行；撞墙要把 `relaxation` 提到 12~20
  并把深度穿透交给外部位置投影。

我最初写文档时把两者混为一谈（都归因到 `biasVel`），核对代码后改掉了。
**教训：诊断之前先确认"这段代码到底有没有被执行"** —— 用 `if (!x.__carId) return`
这类成员标记做分流的函数，光看代码体很容易误判覆盖范围。

### 方案要点（文档内含完整数学与可直接落地的 JS）
1. **方案 A 分离位置投影（Split Impulse）**：位置修正走伪速度独立通道，**不写回 velocity**
   -> 从根本上消除"撞深了就弹飞"。对应 P0。
2. **方案 B 速度依赖自适应恢复系数**：`e(v)` 用 smoothstep 从 0.35(2m/s) 降到 0.02(15m/s)。
3. **方案 C 防跳板法线重定向**：法线 Y 分量归零并归一化；Y>0.5（约 30°）放弃解算交给地面约束。
4. **方案 D 悬挂解耦**：冲量 12% 给簧下、88% 经悬挂一阶低通（τ=K/C≈6.4ms）过滤。
5. **方案 E CCD/TOI 的取舍**：**当前不需要** —— 累加器固定 1/60 + 护栏加厚 2.0m 已给出
   算术保证（300km/h 单步位移 1.39m < 2.0m）。**但若将来把 Clock Slewing 的 ±1.5%
   真的写进物理步长，这个保证就失效，必须补 TOI。**
6. **视野遮挡**：建筑高度按**仰角**分级（`h ≤ tan(θ)·lat − 1.2`，直道 θ=17°、弯道外侧 θ=10°），
   远超"限制高度"式拍脑袋。实测现建筑最高 ~370m、落位仅 45.5m -> 仰角 83°，必然堵死视野。
   另加弯道视线扇区剔除 + 相机侧遮挡淡出。
   **顺带发现：上一轮新增的看台落位 21.1m、高 5.2m -> 仰角 10.7°，刚好越过弯道 10° 阈值**，
   建议横向偏移 +2.0 -> +5.0。

产出 `native/timesync/`：`forza_time_sync.h` / `_testkit.h` / `.cpp` / `_test.cpp` / `CMakeLists.txt`。

### ⚠️ 没有编译器，C++ 未编译验证
本机只有 PortableGit / go / node / python，**没有任何 C++ 编译器**（也找不到 MSVC）。
所以：**C++ 源码未经编译，不能声称"可编译"**。做了两件替代验证：
1. 手写括号/圆括号配平检查（4 个文件全部平衡）；
2. **写了同方程的 Python 镜像 `verify_algorithm.py` 把算法真跑一遍** —— 这是唯一真实证据。

### Python 镜像跑出两个真 bug（这就是坚持先验证的价值）
1. **RTT 打平时让最旧样本胜出** —— 原实现按"最旧→最新"扫描 + 严格小于，
   而 `min()` 语义在打平时保留**最先遇到**的。实际网络（尤其空闲局域网）RTT
   精确相等极常见，于是真实阶跃偏移被历史样本压住：T4 收敛不过去、T5 连
   >200ms 硬同步都永远触发不了。**修法：从最新往最旧倒序扫描**（`for (i = n; i-- > 0;)`），
   打平保留最新。
2. **死区分支里 `applied = target` 是瞬时赋值**（注释却写"缓慢归零"，言行不符），
   单帧最多跳 1ms = 死区宽度 —— 正好违背"禁止 Snap"。修法：死区内**什么都不做**。

修后实测：`maxWarp 0.22%`、**单帧最大跳变 0.0367ms**（上界 0.25ms）、
锁定残余误差 8.73ms（抖动 20~120ms 下，理论最坏 50ms）。

### 交付设计要点
- **零堆分配**：窗口用 `std::array<ClockSample,32>` 环形缓冲（1.3KB，构造后无分配）；
  日志用**裸函数指针**（`std::function` 会分配）；无异常、无 `std::string`。
- **单调纳秒时钟**：Linux 用 `CLOCK_MONOTONIC_RAW` —— **不能用 `CLOCK_MONOTONIC`**，
  它会被系统 `adjtimex` 调频，用它会与自己的时钟同步形成闭环自激；
  Windows 用 QPC，Wasm 用 `emscripten_get_now`。
- **三分模块**：`forza_time_sync.h`（生产热路径，inline）/ `_testkit.h`（模拟器与遥测声明）
  / `.cpp`（非热路径实现）。**这是被编译错误逼出来的**：测试需要 `NtpJitterSimulator`，
  但它原本只定义在 .cpp 里，测试只 include 生产头必然编不过。
- PRNG 用 xorshift64* 且**状态只有一份**（原写法"手工把状态推进 2 步"与 `unit()` 的
  移位次数耦合，改一处忘另一处会静默不同步）。

### 两处刻意的工程取舍（都在注释里写明）
- **NTP 偏移的固有误差**：单向延迟不对称时 `offset != 真值`，误差 = (d_out−d_back)/2。
  测试里明确断言"估计值 -19ms 而真值 +12ms"并注明**这是 NTP 性质不是 bug**，
  避免后来者当成缺陷去"修"。
- **首次锁定允许一次对齐**：没有历史连续性时 Snap 无副作用；
  之后只在重连 / >200ms 才允许。

### 镜像抓到 1 个"代码与注释一起错"的真 bug
`DecayFactor` 我写成 `exp(-dt / T½)`，注释还理直气壮写"经过 T½ 秒剩 50%"。
实测 **`exp(-1) = 0.3679`** —— 我把「时间常数 τ」当成了「半衰期 T½」。
正确公式 `k = 0.5^(dt/T½) = exp(-dt·ln2/T½)`（T½=90ms → λ≈7.70/s）。
**这类错在代码和注释里会一起理直气壮地错，只能靠数值断言抓。**

### 修后实测（全部通过）
```
V1  T½=90ms -> 恰好剩 50.0000%（错写法会得 36.79%）；3·T½ -> 12.5%
V2  28/61/144/239Hz 下 180ms 后剩余**完全相同** = 25%，最大偏差 4.44e-16  <- 帧率无关性
V3  纠偏当帧视觉位置 jump = 0.000e+00 m（物理层已跳到权威值，视觉层吸收全部 0.8m 误差）
    之后 1s 内收敛到 0.36mm，每帧位移不超过 车速×dt 的 1.5 倍
V4  姿态误差经 T½ 恰好减半（30° -> 15.000°）；50m 传送误差 -> 直接吸附清零
V5  外推钉死在 250ms 上限 -> 200km/h 时位移 13.75m（不会飞出地图）
V6  帧号回退的包被丢弃
```

### 设计要点
- **`RigidBodyNetSnapshot` 手工补 pad 到 16B 对齐、size=96**，而不是 `#pragma pack(1)`：
  未对齐 vec3 在 ARM/NEON 上有访存惩罚；显式 pad 让任何编译器下布局一致，可直接 memcpy 上线。
  用 `static_assert` 把 size 与**逐字段偏移**全部钉死在编译期。
- **`SnapshotMailbox` 用 seqlock**（单生产者单消费者，无锁无分配）：
  快照才 96B，拷贝远比 futex 唤醒便宜；语义是"最新覆盖旧"，正是 seqlock 的强项。
  `seq_` 用 `alignas(64)` 独占缓存行避免伪共享。
- **`k = exp(-dt·ln2/T½)` 而非每帧乘固定系数**：后者在 144Hz 上衰减快 2.4 倍。
- 位置的指数衰减与四元数 `slerp(identity, q, k)` **共用同一个 k**，
  否则会出现"位置已对齐、姿态还在转"的割裂感。
- 加速度是二阶量、误差随 t² 放大，所以它的信任窗口（100ms）**必须短于**
  位置外推上限（250ms）；角速度同理（150ms）。
