## 用户第 4 次重发同一需求 —— 没有重做，补了一处"我自己的过度声明"

交付物已完成且真 GLM 1.0.3 全绿（29+21）。重发时改了策略：**不重做，去找自己文里说过了头的地方**。

### 补的这处：seqlock 的"无锁安全性"是**有条件**的，我之前没写清
`SnapshotMailbox` 的载荷 `slot_` 是 96 字节的**非原子**结构体：写者改它的同时读者可能正在读，
严格按 ISO C++ 讲构成 **data race（UB）**。这是 seqlock 的通病（Linux 内核 `seqlock.h` 也这么干），
但我头文件里只写了"无锁安全性"，没写这个前提 —— 属于**把有条件的东西说成无条件**。

现在补上：
1. **用编译期断言把取舍钉死**：
   ```cpp
   static_assert(!std::atomic<RigidBodyNetSnapshot>::is_always_lock_free, ...);
   ```
   实测在本平台成立 —— 证明 96B 的 `std::atomic` 会**退化成内部加锁**，
   所以"用原子对象规避 UB"这条路会直接违背"无锁"要求本身。这把口头取舍变成了**证据**。
2. 写明两条**严格符合标准**的替代方案：
   (a) `std::atomic<RigidBodyNetSnapshot>`（96B 会退化成锁，已由上面断言排除）；
   (b) **双缓冲 + `atomic<uint32_t>` 索引翻转**（96B×2 可接受，推荐）——
       若项目有合规/认证要求应切到 (b)。

### 一句话教训
写完"无锁"两个字之后，要能立刻回答"**在什么前提下**无锁"。
答不上来就说明那句是宣传语不是技术描述。

### ✅ 真正验证到的东西：TS ↔ C++ 线格式契约（43/43）
这里最高风险的不是编译，是**二进制契约漂移**（症状是"位置偶尔错乱"，极难查）。
做法：
1. `layout_probe.cpp`（普通 g++）吐出 `sizeof/offsetof` + 一份**已知取值的参考字节块**；
2. 验证器从 `snapshotLayout.ts` 的**源码文本**里抠出偏移常量，与 C++ 真值逐个比对（防漂移）；
3. **用 Node 22 的原生 TS 类型剥离（`--experimental-strip-types`）直接 import 出货的 .ts**，
   拿真实的 `decodeSnapshot` 去解 C++ 的参考字节块 —— 验的不是镜像，是要发布的代码；
4. `quatFromColumnMajor` 的 Shepperd 提取做了 7 组姿态（含 180° 边界）。

### 验证器抓到我 TS 里的 2 个真 bug（没 tsc 也照样抓到）
1. **`private static #emptyStats()`** —— `#name` 本身即私有，不能再加 `private`。**语法错**。
2. **`const enum`** —— Node strip-only 模式直接拒绝；更要紧的是它在
   **isolatedModules / esbuild / Vite** 下是已知麻烦源（前端 Wasm 工程大概率用这些）。
   改成「`as const` 对象 + 同名类型别名」，零代码生成、任意打包器一致。

### 设计要点（都写进注释了）
- **热路径不用 Embind**：Embind 的 `val`/`string`/`vector` 每次调用都分配+拷贝。
  60Hz 路径改成 `extern "C"` + `EMSCRIPTEN_KEEPALIVE`，参数只有 WASM 堆指针，
  C++ 侧 `reinterpret_cast<const RigidBodyNetSnapshot*>` 直接读 —— **零拷贝**。
  Embind 只留给低频接口（配置、遥测）。
- **必须显式导出 extern "C" 符号**：`-sEXPORTED_FUNCTIONS=...`，
  否则 LTO 会把它们当死代码删掉（这个坑很隐蔽）。
- **Emscripten 堆增长会 detach 视图**：`HEAPU8.buffer` 在 `_malloc` 之后可能失效，
  旧 TypedArray 全部悬空。客户端每包做一次 `byteLength === 0` 兜底检查 + 重建视图；
  矩阵视图**每帧重建**（是极轻的视图构造，不是拷贝）。
- **DataChannel 必须 `ordered: false, maxRetransmits: 0`**：旧快照没有价值，
  不该让一个丢包拖住后面 20 个新快照（TCP 式队头阻塞）。
- **时钟 slewing 传基准步长**：`_forzaClockAdjustedDt(baseDt)`，
  **不是** `frameDt * (1+warp)` —— 规格要的是微调积分步长贴合服务端时间，
  缩放真实帧间隔会引入刷新率相关的手感差异。
- **Babylon 走 position+quaternion 分解**（不是矩阵直写），所以提供了
  `quatFromColumnMajor`（Shepperd 法，180° 附近不炸）+ `eulerFromQuat` 兜底。

## 第十五轮：Wasm/Emscripten 胶水 + TS 宿主（`native/wasm/`）

### 交付
- `network_physics_bridge.h` —— **不依赖 emscripten** 的桥接核心（零拷贝暂存区 + 矩阵暂存区）
- `bindings.cpp` —— Embind + `extern "C"` 零拷贝 ABI（**薄封装**）
- `NetworkPhysicsClient.ts` —— TS 单例宿主（RTCDataChannel / 二进制 / rAF / Three&Babylon）
- `CMakeLists.txt`、`bridge_test.cpp`、`verify_layout.mjs`

### 关键设计决策
1. **把"易错且不报错"的部分做成可原生编译/测试的**。本机没有 emcc，
   Embind 那层编不了；但真正会静默出错的是**字节协议**（JS 写到哪个偏移、字节序、commit 时序）。
   于是把协议实现放进不依赖 emscripten 的头文件，`bindings.cpp` 只做导出。
   `bridge_test.cpp` 完全不调 C++ setter，**纯按字节偏移灌数据再 commit**，
   等价于浏览器里 `HEAPU8.set(payload, addr)` 之后的一切。
2. **零拷贝不是"高效解包"，而是"不需要解包"**：线格式 == 结构体布局时，
   整包 memcpy 进暂存区即可（`pushSnapshotRaw`）。代价是 20B padding（见下），
   60Hz×4 车 ≈ 2.3KB/s，可忽略。
3. **偏移从 Wasm 侧导出**（`OFF_POSITION` 等 + `fz_field_offset()`），
   TS 不写死常量 —— 线格式改了只需重编 Wasm，前端自动跟随。
4. **用 double 传纳秒时间戳**：JS 安全整数上限 2^53 ns ≈ **104 天**，
   只要标签页不连续开机 104 天就是精确的。避免 Embind 的 `int64_t`
   （不同 Emscripten 版本映射成 number 还是 BigInt 不一致）。

### 跑测试发现的设计缺口
`Update()` 会**先推进外推再写矩阵**，于是"收到纠偏后想立刻读物理层矩阵"是矛盾的
（调 Update 又把物理层推了一个 dt）。补了 `RefreshMatrices()`：
`commit -> RefreshMatrices() -> 读矩阵`，`Update(dt)` 内部也变成 `repl_.Update(dt) + RefreshMatrices()`。

### 又一处我手算错的数（被 verify_layout.mjs 抓到）
文档里写"96B 里 68B 有效载荷、28B padding"。**实际 76B + 20B**
（4+4+4+12+16+12+12+12 = 76；5 个 `_pad` × 4B = 20，正好对上）。
已在 TS 与校验脚本里改正，并注明"这两个数别手算，跑脚本"。

### 四个浏览器侧限制（写进 TS 文件头，免得后来者当 bug 查）
1. **时间精度不是纳秒**：`emscripten_get_now()` 基于 `performance.now()`，
   浏览器出于 Spectre 缓解**故意降精度**（Chrome ~100µs、Firefox 默认 1ms）。
   "纳秒"只是类型余量，**不要声称浏览器端纳秒精度**。想更高精度需 COOP/COEP 跨源隔离。
2. **CSP 必须放行 wasm**：`script-src 'wasm-unsafe-eval'`。
   本项目 `index.html` 现在是 `default-src 'none'`，**必须改**，否则静默失败。
3. **`-sSINGLE_FILE=1` 是本项目硬要求**：否则要 fetch `.wasm`，被 `default-src 'none'` 拦掉。
4. **NTP 采样不能走不可靠通道**：快照丢了无所谓（下一帧会来），
   但 PONG 丢了少一个窗口样本、乱序还会被 T1 回退过滤拒收 -> 必须另开可靠通道。

### 验证现状（92 条断言，exit 0）
```

wasm bridge   23 通过    layout 交叉校验 19 通过
```
**未验证**：Embind 层（无 emcc）、TS 类型检查（无 tsc）。
Embind 只是薄封装，风险已尽量压到可测的那部分；TS 侧做了"从模块读偏移"的设计

### ★ 本轮抓到并修掉的两个**真实现 bug**（都是单测抓出来的，不是自审）

**Bug 1 —— 分离判据符号写反（致命：车会穿墙）**
法线约定 `n` 从 A 指向 B ⇒ `v_n = (v_A−v_B)·n > 0` 才是**接近**。
原实现写成 `if (vn > 0) skip`，把"正在接近"当成"正在分离"全部跳过 ⇒
**任何碰撞都不解算，车以原速穿墙且无报错**（`skippedSeparating=1`、`maxΔv=0`）。
改为 `if (vn < 0) skip; closure = vn;`。修后 30m/s 撞墙 → `vx=−0.60`（与 e=0.02 自洽）。

**Bug 2 —— 位置相与速度相方向约定相反（致命：越修穿透越深）**
速度相是 `v_A -= J·invMassA`（A 沿 −n 退，正确）；位置相却写成 `p_A += n·dx·wA`
——把车**推进墙里**。两相必须同号。改为：
```
p_A -= n · dx · w_A
p_B += n · dx · (1 − w_A)          // 静态体同样用 !IsStatic() 守卫
```
> 教训沉淀：**同一模块里"法线方向"这种全局约定，必须在两相处各写一次注释钉住，
> 并且单测要在"两车互推间距是否变大"这类可观测量上断言**——只断言"位移非零"
> 是抓不到方向反了的。C6 原本的对称断言 `a.x == −b.x + 1` 在方向反了时**照样通过**
> （因为对称），已改成断言**间距变大**。

### 混沌网络实现要点
- **单线程 + 模拟墙钟排序投递**（不用真的 `sleep`）：`DrainArrived(nowSec)` 按到达时刻排序，
  以此建模 UDP 乱序。发出/丢弃/投递/乱序/压后全部计数可断言。
- **NTP 四时间戳**：`t2` 必须用**该包的真实单程延迟**盖戳（`SampleLatencyMs()`），
  `t4` 用**实际到达时刻**。曾用固定 40ms 假定值 → RTT 算出 18ms 的怪值（小于单程下限）。
- **确定性**：xorshift32 + Box–Muller，禁用 `rand()`/默认种子 mt19937 → 日志逐字节可复现，
  两次运行 `diff` 完全相同，可当回归基线。

### 揪出的三个真实缺陷（全部是**压测场景自身**的问题，不是算法 bug）
- **[D1] "位置冻结 + 速度未消" = 伪造瞬移源**（最重要）。
  墙相位曾写成 `if (!wallPhase) { A推进; B推进; }` —— A 进墙后 **B 也停了**，
  但 `B.vel` 仍是 −27.78m/s。服务端于是在广播**自相矛盾**的权威状态（位置不动、速度 100km/h）。
  纯远端客户端 B 在丢包间隙按 27.78m/s 外推，越过 `snapDistanceM(5m)` 触发硬吸附
  → 每 ~300 tick 一次 ~4.8m 倒退瞬移（实测 tick 570/866/1144，权威位置恒为 −47.13）。

## 第二十二轮 · 时间同步模块深度审计 + 重构（`native/timesync/`）

用户要求以"3A 拟真物理联机网络底层时间系统架构师"身份审计并重构时间同步模块，

（30 窗、前 20% 低 RTT 加权、±1.5% slew、250ms 硬同步、三个规格接口名）。

### 审计结论：列出的三条里两条**本来就达标**，真正的缺陷在别处
| 用户列的"漏洞" | 审计结果 |
|---|---|
| ① 时钟源带系统回拨风险 | **已达标，且比要求更严**。原实现 Win=QPC、Linux=`CLOCK_MONOTONIC_RAW`、Wasm=`emscripten_get_now`。`steady_clock` 只是兜底 —— 在 Linux 上反而更差（`CLOCK_MONOTONIC` 被 adjtimex 调频 → 与同步器闭环自激）。按规格把 `steady_clock` 显式写成保证性回退路径并注释清楚。 |
| ② 算术平均 RTT 被长尾污染 | **不是均值**，原本就是"单点最小 RTT"。真正问题是**单点极值脆弱**（一次双向皆低的幸运采样独占权威估计）。这是要修的点，但性质与"均值污染"不同。 |
| ③ 修正直接改本地物理时间 | **已达标**，从来就是 slewing。 |

### 又揪出两个**真实缺陷**（"物理 Tick 抖动"的实际根因）
- **[E1] 生效偏移推进量与 `dt'` 的定义割裂**。
  旧式 `appliedOffset_ += warp * baseDtSec * 1e9` 近似等于 `(dt'−baseDt)`，看似等价；
  但一旦将来给 `dt'` 加夹取（物理引擎要求 dt 下限），两者立刻失配 → **残差稳定在非零值上不收敛**。
  修法：`appliedOffset_ += (warpedDt - baseDtSec) * 1e9`，保证定义自洽。
- **[E2] 死区把残差永久冻结**（更要命）。
  旧代码 `if (|err| <= deadband) { warp_ = 0; return baseDt; }` 且不推进 `appliedOffset_`
  → 死区内残差被**永久冻结**。后果：局域网里常见的 <1ms 恒定相位差（服务端 tick
  vs 客户端帧率的固有偏差）**永远收敛不掉**，表现就是物理 Tick 长期微幅抖动 ——
  正是用户描述的症状。修法：死区内也按同一方程算 warp（残差小则 warp 本就极小，
  自然被 ±1.5% 夹住内）；死区只用来设**状态标签**（Locked/Slewing）避免 HUD 闪烁。

### 抓到并修掉的两个真 bug

**① 量化舍入与 JS `Math.round` 不等价（只会在跨语言互操作时现形）**
`0.0625 × 8 = 0.5` 是精确半值。C++ 用了 `std::nearbyint`（**银行家舍入** → 0），
JS `Math.round` 是**朝 +∞**（→ 1）。scale=8 让 `0.0625/0.1875/0.3125` 全是精确半值，
**不是边角料** —— 两车位置会稳定差 0.125m。
先误修成"远离零"（`ceil(x-0.5)`），在 node 里逐值验证 JS 语义后发现
`Math.round(-0.5) = -0`、`-1.5 → -1`、`-2.5 → -2`，**半值朝 +∞**，
最终统一成 `std::floor(s + 0.5)`。
→ 教训：**只有 C++↔TS 逐字节对拍能发现这类 bug，JS↔JS 自测永远看不见**。

**② 起步锁是永久锁（`S.raceClock < 0`）—— 玩家踩油门车不动**
`sampleLocalInput` 的发车门写成 `S.raceClock < 0` 就清空油门。但
`raceClock = (Date.now() + simOffset) − raceStartAt`，而 `raceStartAt` 的写入时机：
- 离线：`beginRace({ startAt: Date.now() + 2600 })` → 差值**恒 ≈ −2600ms**
- 联机：服务端 `startAt = now + 700ms`，再经网络到达客户端 → 同样为负

于是**整个倒计时、以及 GO 之后**，`raceClock` 一直是负的 ⇒ 油门被永久清零。
唯一正确判据是 `S.rp.racing`（由 `raceClock >= 0` 推出，且每帧更新）。
本机**没有 Go 工具链**（C 盘 `Program Files/Go`、`C:\Go`、D/E 盘均无 `go.exe`，
只有 `AppData/Local/go-build` 缓存残留），所以改的是**静态可验**的问题：
- `sampleLocalInput` 改用 `!S.rp.racing`
- 时钟段补 `raceClock < -0.001` 兜底夹取 + 一次性 `console.warn`（暴露"不在同一时间轴"）

## 规格要点（全部实测达标）
- **仿真-墙钟替代真线程+sleep**：单线程确定性，同 seed ⇒ 日志逐字一致（可当回归基线）。
  16s 仿真 32ms 压完（30,968 fps）。
- **★ 非对称长尾抖动 = 对数正态** `LogNormalMs(median, sigmaLog)`。
  真排队延迟是**乘性右偏**过程（M/M/1 → 指数/对数正态长尾）；高斯衰减太快，
  会把"偶发 160ms 尖峰"抹掉——而那个尖峰才是真正触发 rubberbanding 的东西。
  实测 max/mean = **2.77**，区间严格 [20.0, 160.0]ms。
- **乱序必须由两包真实到达时刻倒挂产生**（一包"抢跑" `reorderLeadMs`），
  不能"把后发包延迟"——否则接收侧永远看不到 seq 倒挂，`outOfOrder` 计数器是空的。
  实测乱序 9337 / 注入抢跑 532。
- **NTP 时间戳语义**：`t1`=本地发送；`t2`=对端接收（对端钟）= 本地时刻 + **本包实际**
  单程延迟 + 固定偏移；`t3`=对端回发（+2ms 处理）；`t4`=本地收到。
  **`t2` 必须用本包真实延迟**，不能用均值（否则 RTT 算出错误的亚单程值）。
- **★ Jerk（加加速度）= 位置的三阶差分**：`jerk = |a_n − a_{n−1}|/dt`，
  `a=(v_n−v_{n−1})/dt`，`v=(p_n−p_{n−1})/dt`。这是 rubberbanding 的物理定义
  （人的前庭系统对 jerk 敏感）。正常插值 jerk ≈ 0；1/60s 内瞬移 0.5m ⇒ jerk≈0.5/(1/60)³。

## ★★ 本轮两大发现（都是"测试自身错了，不是被测错了"）

### 1. 接触点相对速度 ≠ 质心相对速度（决定性问题）
追尾断言最初写"质心法向分离 ≈ 0"→ 实测 +21.09 m/s，看着像求解器炸了。

invI=1/3000, rz=0,   2点(物理)     +2.0628    +0.0000    +0.0000       -49.5%
invI=0(球),  rz=1.2, 2点            +0.0000    +0.0000    +0.0000       -50.0%

**偏心撞击时冲量在线性/角向间分配，质心相对速度本就不归零，归零的是接触点。**
