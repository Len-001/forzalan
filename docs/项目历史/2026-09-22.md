# 2026-09-22

## 极限竞速 · LAN —— 四人局域网 3D 网页赛车（全离线单文件）从零重构

### 交付形态
Go 单文件可执行 + `//go:embed all:public`，前端零外部请求（three r128 + cannon-es 全部本地化）。

```
go.mod / main.go
public/index.html  style.css
public/libs/{three.min.js(r128,592KB), cannon-es.js(0.20.0,340KB), package.json}
public/js/{track,physics,network,main}.js
tools/{selftest.mjs, e2e.mjs, fetch-libs.sh}   ← 自建验证链
```

### 关键工程决策
1. **服务端 WebSocket 手写实现**（RFC6455 握手 + 帧编解码），go.mod 零第三方依赖 → 离线机器也能 `go build`。
   实测：扩展长度帧（payload>125B）、ping/pong 保活、30.0Hz 中继全部通过。
2. **Cannon-es 只做车对车，路面用解析法**：cannon-es 没有 convexTrimesh（Trimesh vs Box 窄相缺失），
   所以赛道不做网格碰撞，改为 `track.sample()` 解析贴地钳位 + 摩擦圆限幅。性能恒定且四车参数严格对等。
3. **权威划分**：服务端定房间/倒计时/发车时刻/罚时累计/成绩；客户端跑物理与 Checkpoint。
   发车时刻用 ping/pong 时钟同步（offset = s - (c + rtt/2)）统一四台机器的时间基准。
4. **横摆角速度被摩擦圆锁死**：`|ψ| <= μ·g/v`。这是让"高速打方向只会推头"成立的关键，
   否则弯道会变成贴轨过弯。AI 必须做**刹车距离前视**（扫前方 240m 曲率），只看 40m 会在发夹弯冲出去。
5. 坐标系约定（最易出错）：`right = up × forward`、`forward = local +Z`；
   `track.side = cross(tXZ, up)` 其实是"左侧"，发车位基向量必须 `-side` 才对。

## 第二轮：驾驶手感专项修复（转向 / 动力 / 手刹 / 漂移 FX）

### 核心发现：转向反向的真实根因
右手系下 `right = forward × up`。车头朝 +Z、车顶朝 +Y 时：
`right = (0,0,1)×(0,1,0) = (-1,0,0)` ⇒ **局部 +X 是车身左侧**。
上一版把它命名为 `c.right` 并映射成 D/→，于是按 D 实际向左转。
AI 用同一套向量所以自洽 —— 上一版测试只断言了"基向量正交 + 车头对准切线"，
**从未断言"steer>0 往哪边转"**，所以漏了。教训：方向类 bug 必须断言"位移落在车体哪个方向"。

修复：显式区分 `lateralDir`(+X 左轴) 与 `rightSide`(-X 真右)，并在 `driveLocal` 里
用唯一的负号 `steerAngle = -steerInput * maxSteer` 完成校准，注释写死原因。

| 0-100km/h | ~5.3s | 5.28s（旧的 MAX_FORCE=12500 是 9.6m/s² 火箭） |
| 风阻 | 0.5·1.225·0.35·2.2·v² | 实测合力 971N vs 理论 931N |
| 转向限幅 | 0.55→0.15 rad | 30/75/120km/h → 0.550/0.350/0.150 |

### 漂移 FX 实现要点（全在 main.js，无新文件）
- 烟雾：`THREE.Points` + 200 粒子池 + 自写 GLSL（per-instance alpha/size/color）+ CanvasTexture 光斑，
  零外部贴图；寿命 0.6s，向上膨胀，alpha→0。
- 胎痕：单个 BufferGeometry（900 quad、Uint16 索引）+ 环形复用，每 0.05s 铺一段接成带，
  y=地面+0.02，8s 生命周期 + 2s 渐隐，换赛道时 reset。
- `?drift=1` 自动驾驶漂移演示 + `burst()`：专门给无头截图用的一次性补量。

### 踩坑
- 漂移测试**不能**用"每步把车头扳回切线"的直道台架 —— 那等于每步抹平横摆，侧偏角永远涨不起来（假阴性）。
- 手刹减速度别按"急停"写断言：5000N/1300kg 只有 3.85 m/s²，0.5s 约 7km/h，别把符合物理当缺陷。
- AI 需要"出界自救"（偏离 >3m 时放弃走线、限速、瞄中心线），否则被撞飞后会一路跑进树林（60m→33m）。

## 第三轮：全面 FM8 拟真重构（看齐 Forza Motorsport 8 车辆动力学）

### 交付方式教训（重要）
第一次尝试**整文件重写** physics.js(1000+行) + main.js(1900+行) → 连续两次被输出长度限制截断。
**正确做法：拆成 10+ 次小颗粒定点 Edit，每改一个子系统就跑一次测试。** 本轮全部用这种方式完成。

### 车辆基准（CFG，全 SI）
m=1380kg / h=0.45m / L=2.70m / W=1.6m / 前后配重 52:48；
扭矩峰值 450N·m@4500rpm，红线 7500rpm，6 档齿比 3.36/2.19/1.60/1.24/1.00/0.83，主减 3.55；
Cd=0.34 / A=2.1 / Cl=0.85 / ρ=1.225；碰撞恢复系数 0.22。

### 实测标定结果（全部有断言）
| 指标 | 实测 |
|---|---|
| 极速 | **265.0 km/h**（扭矩曲线+6档+风阻自然收敛，非硬编码） |
| 0-100km/h | **3.87 s**（MAX_FORCE=15600N ≈1.15g） |
| 载荷转移 | 实测 790N vs 理论 m·a·h/L = 793N |
| 下压力 | 实测 3962N vs 理论 0.5ρClAv² = 3960N @217km/h |
| 高速轴荷 | 17501N vs 车重 13538N（气动压紧 +29%） |
| 下压力提升过弯极限 | 22.1 → 30.6 m/s² |
| 制动前轴载荷 | 7960 → 11447N（前咬后滑，aF 41 vs aR 11） |
| 手刹后轮摩擦 | 2.4 → 0.83（动摩擦区），前轮 2.76 上升 |
| 尾流降阻 | 实测 31%（目标 35%，差额来自未被削减的滚阻） |
| 脏气流降下压力 | 29.5%（-30% 规格） |
| 修正后单圈 | 46s，长跑横向偏移 45.8m（AI 加前车避让后） |

### 关键实现
- **载荷转移替代"魔法降摩擦"**：`axleState()` 用 ΔFz=m·a_x·h/L 算两轴正压力 →
  `a_F_lim = muF·FzF/(m·LR/L)`、`a_R_lim = muR·FzR/(m·LF/L)`，整车横向极限取 min。
  手刹时后轴 mu 崩到 0.85，前轴因载荷前移反而更咬地 → 车尾自然甩出，**推头被物理消除**。
- **下压力必须喂进轴荷**（我第一版漏了）：规格要求"动态增加轮胎正压力"。加上后 AI 的长跑横向
  偏移从 59m 掉到 8.3m —— 因为 AI 改用 `c.aLatCap`（真实横向极限）评估过弯速度。
- 轮胎载荷敏感性容量 ∝ Fz^0.85；侧向转移惩罚 1-0.12·(ay/μg)²。
- 相机：`1-exp(-12·dt)` 指数衰减 + 车后 5.5m/1.8m + 沿**速度向量**（漂移时能看到车头偏角）
  + 注视点车头前 8m 切线（弯心预瞄）+ FOV 60→72@200km/h + 尾流 25Hz/0.015m 湍流 + FOV 微收 1.5°。
- **彻底删除屏幕速度线**（规格严禁）：`drawSpeedlines()` 1764 字符整段删除，HTML/Canvas/CSS 一并移除。
  HUD 尾流提示改为纯白灰极简单行 "DRAFTING"。

### 陷阱复现（写进技能了）
- **测试台架会造成假阴性**：注入初速后头几步 `axMeasured=(v0-0)/dt` 是假的（=900m/s²），
  必须先跑 20~40 步稳下来再测；比对载荷转移时要剔除气动分量。
- "每步把车头扳回赛道切线"的台架等于强迫车按曲率走线，横向抓地被迫抵偿 v²/R 并耗散动能 ——
  测到的是"能跟随中心线曲率的最大速度"，不是动力总成极速。改成固定朝向的**测功机台架**后
  极速立刻从 214 变成 265 km/h。

## 第四轮：三个关键 Bug 底层修复（抖动 / 仪表 / 手刹推头）

### 1. 物理抖动抽搐 —— 真因是"位置瞬移钳位"
旧 `groundConstraint` 每步把 `body.position.y` 硬设到地面高度并清零 vy，
与重力积分形成锯齿 → 车身高频上下颤。改为**临界阻尼悬挂弹簧**：
```
F = K·x − C·vn     K = m·g/(MAX_TRAVEL·0.20) = 225.6 kN/m
                   C = 2·ζ·√(K·m) = 35.3 kN·s/m（ζ=1）
```
冲程限制 0.30m，超出接 bump stop + 硬钳位兜底。实测：
- 静态下沉 **6.00cm**（实测 = 理论 6.00cm，弹簧力与车重平衡）
- 固有频率 **2.04 Hz**（真实赛车区间）
- 阶跃下压 14.3cm → **方向翻转 0 次**（单次归位，无过冲）
- 长跑 maxΔy 从 0.638m → **0.152m**
- 巡航竖直速度残差翻转率 **0.0%**（0/900 步），残差均值 **0.038 m/s**

另外补了**子步插值**：`alpha = acc/substep`，渲染在 prevPos↔pos 之间插值
（等价 cannon 的 interpolatedPosition），消除高刷屏一步一台阶的撕裂。

### 2. 仪表指针错位 —— 真因是两套角度基准混用
表盘弧用 SVG 极坐标（0°=+X 轴），指针元素默认朝上（0°=12 点钟），**相差 90°**。
旧代码把极坐标角度 `-210..+30` 直接喂给指针 → 0km/h 指到右下角。
修法：显式区分两个空间，`polar = -90 + css`：
- 指针：CSS 空间 `angle = -120 + min(kmh,260)·(240/260)`
- 弧线：极坐标 `-210 .. +30`
指针改为独立 HTML 元素 + `transform-origin: 50% 90%` + `transition: transform .05s linear`。
车速改取 `chassisBody.velocity.length()`（规格要求，严禁用车轮转速）。
浏览器实测：0km/h → `rotate(-120deg)` ✔

### 3. 手刹入弯推头 —— 真因是 yawGrip 用了错误的前后加权
`yawGrip` 原本用 `muF·0.52 + muR·0.48`（前后加权平均）。手刹时后轴 μ 崩塌，
加权平均把"已经没抓地的后轴"也算进了"车头能转多快"，于是横摆被锁死 → 推头。
**转向力矩来源只可能是前轴**，故改为 `yawGrip = muF·9.81·1.06/|vF|`。
同时按规格把前后配比拆开：常规 2.6/2.4，手刹 **前 3.2（严禁抱死）/ 后 0.45**，
释放 0.2s 平滑恢复（防 Snap Oversteer），并加入与转向同向的横摆角冲量
（规格式子 mass×1.8 若当角加速度是 2484 rad/s²，大 3 个数量级，标定为 5.0 rad/s²）。

实测：手刹横摆峰值 **2.26 rad/s vs 常规 1.30**（+74%），侧偏角 **83.5°**，
muFront 2.95 / muRear 0.372。

`node tools/selftest.mjs` → **149 项断言全过**；`node tools/e2e.mjs` → **56 项全过**。

## 第五轮：转向滤波 / PIT 别车 / 动态走线 / 多视角

### 1. 转向滤波与低速线性度
- 废除上一版的**线性限速**（0.12s 匀速打满），改用规格的指数滤波
  `steerInput = THREE.MathUtils.damp(steerInput, target, 8.0, dt)`。
  实测：1τ=0.133s→63%、3τ=0.383s→95%（前期快后期缓＝手打方向盘行程）。
- 低速非线性：`<40km/h` 时 `有效量 = sign(i)·|i|^1.6`，实测 0.5 输入 → 0.330；
  高速淡出后同一输入 → 0.500。40km/h 处按 15km/h 宽度线性淡出，避免手感断层。
- **规格冲突处理**：上一轮要求"0.15s 匀速回正"，本轮要求 λ=8 指数滤波。
  本轮更新，旧断言按新语义重写（1τ/3τ 判据）。

### 2. PIT 别车与偏心碰撞力矩
- 明确：**AI 本来就是纯力学驱动**（只写 input，不碰 position/quaternion）；
  只有网络远端车用伺服（那是插值代理，不是 AI）—— 已在代码注释里写清。
- `angularDamping` 0.35 + 新增 `yawDisturb` 扰动窗口（0.35s 内横摆修正权限降到 20%）。
  这才是"撞了有反应"的关键：光降阻尼没用，控制器 0.1s 就把碰撞角速度纠回来了。
- 真因修复：碰撞用 `(r×J)_y = r.z·J.x − r.x·J.z`，**除以 I_yy 而不是 mass**
  （规格写 `torqueY/mass` 是量纲错误；I_yy=2213 kg·m²，差 1.6 倍）。
- **PIT 判定不能用"接触点横向偏移"** —— cannon 报的是接触流形里的某个角点，
  正后居中对撞也会报到角上（假 PIT）。改用**两车中心线横向错位**（>0.7m）。
- 实测：别车 yaw 峰值 2.93 rad/s、pitHits=1；正后追尾 pitHits=0。
- 碰撞材质按规格改为 restitution 0.3 / friction 0.4。

### 3. 动态最佳走线
- `track.js`：曲率→外-内-外偏移→1.2m 宽、悬浮 0.04m 的封闭色带。
  数学部分拆到 `_computeRacingLine()`（构造函数就执行，不建网格也有数据）。
  实测：直线偏移均值 0.39~0.64m、弯道 5.02m（结构成立）；|offset| ≤ 半路宽−1.0m 不越界。
- `main.js`：30Hz 按 `v_max=sqrt(μ·g·R)` + 制动距离反推 `v_allow=sqrt(v²+2ad)`
  与当前车速比较 → 绿 #00ff00 / 黄 #ffff00 / 红 #ff0033。
  交叉验证：AI 实际车速 / 走线极限 = 峰值 0.90×、均值 0.56×（数值物理自洽）。

### 4. 多视角（C 或 V 循环）
- Mode 0 追尾（默认，5.5m/1.8m + 速度向量）／Mode 1 引擎盖（离地 0.9m、FOV 75）／
  Mode 2 垂直鸟瞰（车顶正上方 35m、垂直向下、**up = 车辆后方向量** → 车头朝屏幕上方）。
- 鸟瞰必须**在 lookAt 之前**设 `camera.up`，切回其它视角要恢复 `(0,1,0)`，否则姿态残留。
- 新增 `?cam=0|1|2` 调试参数 + `L` 键开关走线。截图验收：鸟瞰下车头朝上、走线呈亮绿色带。

## 第六轮：非弹性剐蹭 / 沙地陷阱 / 救援复位 / 60Hz 网络同步

### 1. 非弹性碰撞与切向剐蹭冲量截断（physics.js）
- 接触材质按规格：restitution **0.02** / friction 0.35 / stiffness 1e7 / relaxation 3。
- **关键发现**：cannon 的 `collide` 事件**只在接触建立那一步派发**，持续接触不再触发；
  而"剐蹭弹开"发生在**接触后的第 1 步**（4cm 重叠被接触刚度弹出 3.836 m/s）。
  因此改成**粘性软接触**：撞击步（法向相对速度 < 3.5m/s）登记一个带 TTL(8 步) 的
  接触对，随后每步持续把"正在分离"的法向速度按动量守恒冲量削减 75%。
  实测：截断后 0.958 m/s vs 未截断 3.836 m/s —— **精确保留 25%**。

### 2. 赛道外沙地减速陷阱
- 规格的"路面阻尼 0.05" **没有采用**：本底盘的路面阻力已由显式气动+滚阻建模，
  再叠 cannon 全局阻尼等于双重计阻力（73m/s 时多出 ~5000N，直接打崩标定的 265km/h）。
  沙地端严格按规格 **0.45** —— 关键是"沙地相对路面的阻尼增量"，该增量与规格一致。
- 其余：>2 轮出界触发、推力衰减 60%、硬限速 40km/h、侧向摩擦 0.6、1.0s 平滑恢复。
  实测：全油门沙地峰值 13km/h，恢复 1.00s。

### 3. R 键救援复位
上一个合法通过的 Checkpoint 中心上方 0.5m + 对齐切线 + 清零线/角速度 +
罚时 3.0s + 3 秒冻结（满刹锁死、禁油门、屏中央半透明倒计时横幅）。
实测：水平偏差 0.000m、高度 0.500m、fwd·tan=1.0000、冻结期 0.2km/h、解冻后正常起步。

### 4. 60Hz 快照插值网络同步
- main.go：`time.NewTicker(16666 * time.Microsecond)`，60Hz 广播，包带 ms 时间戳。
- network.js 完全重写：
  · 30 帧 TypedArray **环形缓冲**（T/P/Q/V 四个数组，零 GC）
  · 固定渲染延迟 **50ms**，renderTime = now − 50
  · 位置用 **Hermite 三次样条**（以线速度为端点切线）—— 实测匀速直线还原 x=10.000
  · 姿态 SLERP —— 实测 45.0° 精确中点
  · 丢包时按速度直线外推（实测 18.8m/s，250ms 上限截断）
  · **误差融合**：目标位置被新快照拽回时，渲染位置按 1−exp(−14·dt) 指数收敛
    —— 实测单帧位移峰值 **0.33m**（直接赋值会瞬移 ≈2m）
  · 乱序包（时间戳早于队尾）丢弃
- 客户端上报频率同步提到 60Hz（否则 60Hz 广播只是在重发重复数据）。
- e2e 实测中继 **60Hz** 通过。

### 本轮踩坑（全是台架问题）
- 车距 0.925+0.925=1.85m 我当成"接触"，实际车宽 1.8m 是 **5cm 间隙** → 改成 0.88。
- 又忘了解冻后清 brake/handbrake（冻结期被强制置 1）→ 车被刹车按住不动。
- 弯道上测横向分离速度会被曲率污染出 2.7m/s 假信号 → 必须选最平直段 + 锁死朝向。
- 测"外推"时不能拿单帧渲染值与解析值对比 —— 误差融合本身带一帧滞后（刻意设计）。
