# 极限竞速8 修复记录（2026-10-12）

项目：`D:\极限竞速8\极限竞速8`

本次修复前次检查报告中的 9 项问题，另修复了旧报告中已知的 AI 事故车避让失败。沿用 Go 标准库、现有物理模型和 Worker 架构，没有添加依赖。

## 修复内容

| 问题 | 修复后的行为 |
| --- | --- |
| 结算与在线查询互锁 | 在线玩家、房间信息和人数查询先复制 Hub 注册表，再逐房读取；不持有 Hub 锁等待房间锁，结算和改名不会与这些查询互锁 |
| Worker 名册初始化不完整 | 一次补齐本地/远端标记及服务端发车格，镜像与 Worker 使用相同初始化参数；重复建车直接复用已有车辆 |
| 每台机器独立模拟 AI | 联机 AI 只由房主模拟，加入者接收远端快照；房主退出时转移物理控制权和圈数、检查点、单圈计时、罚时等状态，并重置服务端旧序号 |
| 跨圈不重置检查点 | lap 和 state 共用跨圈重置逻辑，两种报文先后顺序都正确 |
| 控制队列满时静默丢事件 | 关闭积压连接，使断线处理生效；快照队列积压仍可丢快照，不影响控制队列 |
| 同一连接重复入房/建房 | 服务端在改名和加入前拒绝重复请求，底层 attach 也拒绝已入房成员 |
| 红灯、零圈、负用时完赛 | 服务端验证正式开赛、发车时刻、完成圈数和合法成绩；脏的最终圈也能正常完赛，但不写入干净最佳圈 |
| 罚时原因被截断 | 保留完整协议原因，`frr_gain`、`shortcut` 可正确统计违规次数和显示中文原因 |
| 脏圈标记不同步 | 在物理 Car 处罚入口记录脏圈，通过事件和 Worker 状态包同步；下一圈由物理状态清除 HUD 标记 |
| 旧 AI 避让失败 | 将仍有碰撞体的退赛车纳入前车检测，预警距离增加 1 米；原失败场景保持约 9.28 米间距，原先约 4 米 |

延迟测量同时统一使用 `pingMu`，避免房间快照和 ping 更新使用不同锁。Worker 状态步长由 84 增至 88，远端传输步长由 21 增至 34，相关生产者、消费者和测试一起更新。
